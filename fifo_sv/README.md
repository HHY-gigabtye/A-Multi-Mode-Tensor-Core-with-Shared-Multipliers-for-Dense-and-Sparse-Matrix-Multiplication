# FIFO / Bridge Standalone Unit Verification

This package verifies only `du_tc_bridge`. The testbench instantiates no MLU,
DU/TIA, Tensor Core, or MSU. Verify each unit independently before full-system
integration.

The original packaging revision removed the partial-integration wrapper,
integration testbench and scripts, and RTL for other units. It retained
`du_tc_bridge.sv`, `du_tc_bridge_pkg.sv`, and `tb_bridge.sv` without changing
hardware interfaces, timing, credit accounting, or metadata behavior.

## ModelSim / Questa

Extract the complete ZIP, preserving `vectors/`. In the Transcript, change to
`fifo_sv` and run:

```tcl
do run_bridge.do
```

An absolute script path also works:

```tcl
do {C:/your_path/fifo_sv/run_bridge.do}
```

The script compiles four files in this order and simulates `tb_bridge`:

| Order | File | Purpose |
|---|---|---|
| 1 | `tensor_core_pkg.sv` | Shared packet types and constants; no TC circuitry |
| 2 | `du_tc_bridge_pkg.sv` | Bridge state, metadata, and FIFO entry types |
| 3 | `du_tc_bridge.sv` | The only hardware unit under test |
| 4 | `tb_bridge.sv` | Drives Bridge ports and checks results |

The FIFO needs `tc_input_packet_t` from `tensor_core_pkg.sv`. **Compiling the
package does not instantiate Tensor Core.** This package contains no
`tensor_core.sv` and runs independently of TC circuitry.

Expected success message:

```text
BRIDGE RTL PASS: C-equivalent rows=19147 rejected_edges=7156 resets=13
```

Expected data is included in `vectors/bridge_vectors.txt`; ModelSim requires
neither C nor Python execution. Checks use procedural `if` / `$fatal`, without
SVA or DPI. The original package was tested with Verilator; its ModelSim/Questa
scripts had not been run at that delivery.

## Modeling external signals without other units

The testbench reads inputs and expected values generated by the original C
model and drives the Bridge boundary directly:

| Bridge ports | Unit-test role |
|---|---|
| `issue / issued_mode / issued_k / issued_meta` | Models an actual upstream issue into DU/TIA |
| `du_valid / du_packet` | Models DU/TIA output after four stages, without running the decoder |
| `tc_accept` | Models acceptance of the FIFO head, without matrix computation |
| `result_accept` | Models acceptance of a tile result and releases metadata |
| `rst_n` | Clears Bridge state while the driver cancels pending events |

Each record checks status, every sideband/FIFO/metadata register, counters,
the head entry, and result metadata. Deliberate contract violations expect a
non-`IO_OK` result and unchanged Bridge state; normal full occupancy is not an
error.

`c_reference/` preserves the supplied C model, headers, and standalone testbench;
only filenames were restored to match their includes. The additional
`generate_vectors.c` invokes the original tests, adds randomized timing with
four fixed seeds, and exports expected values. C and SV packed structures have
different layouts, so conversion is field-by-field rather than a C memory copy.

## Unit coverage

- Continuous inputs, input bubbles, and downstream stalls.
- FIFO occupancy up to 8, inflight occupancy up to 4, and result metadata occupancy up to 2.
- Packet contents, ordering, k, tile ID, and 64-bit destination addresses.
- Same-edge FIFO push/pop, metadata push/pop, and pointer wrap-around.
- Missing credit, metadata-full blocking of new tiles, and DU timing/mode errors.
- Reset with inflight data, queued packets, or queued metadata; no stale data after restart.
- 19,147 input/state records, including 7,156 expected rejections and 13 resets.

These checks cover FIFO/Bridge functionality and cycle behavior. DU decoding,
TC matrix computation, and real MLU/MSU end-to-end handshakes belong to their
unit tests and subsequent full integration.

## Preserved hardware behavior

The packet FIFO has 8 entries, the DU/TIA metadata sideband has 4 stages, and
the result metadata queue has 2 entries.

`fifo_count + inflight_count <= 8`. `issue` reserves credit, DU arrival moves
the reservation from inflight to the FIFO, and only `tc_accept` releases it.
`can_issue` uses old registered state, without same-edge credit reuse.

DU output is written into the FIFO before TC can consume it on the following
edge. There is no payload bypass. The FIFO head is combinational, without an
additional output register.

The current implementation rotates all eight physical storage words on a pop,
so physical slot zero is always the logical head. A simultaneous arrival is
written after that rotation at `count - tc_accept`. The registered
`head_present_q` gates the combinational head; it adds no payload register.
The logical C-model slot order, including stale contents, is reconstructed for
the unchanged unit comparison. Metadata blocking, credit accounting and
non-bypass latency retain their contracts. See the
[BRAM/rotating-FIFO promotion record](../reports/verification/bram_main_20261119/README.md)
for that change and the [current integration record](../reports/verification/operand_route_main_20261122/README.md)
for use with the shared TC.

When the head has `k=0` and result metadata is full, `head_valid=0`. Metadata is
pushed when TC accepts the tile's first packet and popped on the **actual
TC→MSU handshake**, without waiting for HBM writeback completion.

`side[]` is a real four-stage tag pipeline storing only
`valid / is_sparse / meta / k`. External DU/TIA handles the full payload, which
is written into the FIFO after DU/TIA produces it.

| Port | Integration meaning |
|---|---|
| `can_issue` | Whether upstream may issue another packet into DU/TIA |
| `issue` | Actual DU/TIA issue on this edge, not merely a request |
| `du_valid / du_packet` | Old DU/TIA S3 output; no ready port |
| `head_valid / head_entry` | Current packet eligible for TC |
| `tc_accept` | Actual FIFO→TC transfer on this edge |
| `result_meta_valid / result_meta` | Oldest unconsumed result metadata |
| `result_accept` | Actual TC→MSU transfer on this edge |
| `status` | Combinational check of whether current inputs can commit on the next edge |

`head_entry` presents the head whenever the FIFO is nonempty, even when metadata
blocking deasserts `head_valid`. Consume it only when the head is valid and TC
can accept it. An empty FIFO produces zero.

Fields: 32-bit `tile_id`, 64-bit `dst_addr`, and unsigned 8-bit `k` with legal
values 0..7. Mode is 2 bits: 0=dense, 1=hybrid, 2=dual, 3=illegal. Payloads use
the existing packet type and preserve INT8 bit patterns directly.

**A normally full FIFO stalls; it does not report an error.** Upstream must wait
when `can_issue=0`; asserting `issue=1` anyway produces `IO_NO_CREDIT`. Other
statuses include `IO_BAD_FORMAT` and `IO_PROTOCOL_ERROR`. `IO_BAD_ARGUMENT`
corresponds only to C NULL pointers and is not produced by RTL.

As in C, a non-`IO_OK` edge does not commit Bridge state. This diagnoses contract
violations and cannot pause external DU/TIA. Correct the source and reset
related modules together after such an integration error.

Upstream must supply eight packets per tile, k=0..7 in order, with consistent
metadata. Bridge retains the C model's check scope and adds no checks for these
sequence requirements.

## After unit verification

Once every unit passes, connect the full system. Start with one tile in each
mode, then add continuous tiles, input bubbles, and output stalls. A separate
DU/TIA + FIFO + TC partial-integration stage is not required.

Reset DU/TIA, Bridge, and TC together and align the sideband to the actual
four-stage DU/TIA latency. In the production top, normalize dense operands to
counts of eight and indices `0..7` before FIFO insertion; sparse operands keep
their decoded counts and indices. The packet's `is_sparse` tag still checks
DU/TIA provenance against the sideband. The TC receives only
`head_entry.packet.payload.sparse`, a 184-bit indexed operand pair for every format.

The shared `outer_product_core` uses strict, result-credit-based admission:
`tc_accept = rst_n && head_valid && tc_in_ready`, with that pulse also driving
TC `in_valid`. A new tile reserves one of two result slots; subsequent slices
use its reservation. Keep the stored payload connected while waiting. The
production TC has no mode input or `input_ready` output, and format changes
need no drain. Mode-aware readiness belongs to the retained legacy TC only.
See the [current TC contract](../tensor_core_sv/README.md).

## Linux reproduction

```bash
python3 run_tests.py
python3 run_tests.py --regenerate
python3 run_tests.py --trace
```

All three commands test only FIFO/Bridge. The first uses included expected
values; the second requires gcc and reruns the original C model and tests;
the third writes `bridge.vcd`. Simulation requires Verilator and a C++ compiler.

The script uses `-O0` to avoid incorrect constant folding of post-loop testbench
statistics by the Verilator build used in the original environment. This changes
optimization of generated simulation C++, not RTL. The verified Linux/GCC
precompiled-header settings are also retained.

At the original delivery, FPGA/ASIC synthesis and P&R had not been run; no new
Fmax, area, or power results were claimed.
